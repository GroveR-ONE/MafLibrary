# МАФ · Библиотека изделий

Локальное веб-приложение-каталог для изделий МАФ. Сервер, база каталога и загруженные файлы хранятся на Windows-компьютере; пользователи открывают каталог браузером по HTTP в доверенной локальной сети.

## Запуск

Необходим .NET 10 SDK на серверном компьютере.

1. Распакуйте проект в папку сервера.
2. Задайте PIN для режима редактирования (рекомендуется сменить начальный `admin`). Например, в PowerShell:

   ```powershell
   cd C:\Users\Konst2\Documents\MafLibrary
   $env:MAF_ADMIN_PIN = 'ваш-общий-pin'
   .\start-library.bat
   ```

3. Если переменную не задавать, PIN — `admin`. Сервер слушает порт `5080` на всех сетевых интерфейсах.
4. На серверном ПК откройте `http://localhost:5080`. На других устройствах — `http://ИМЯ-КОМПЬЮТЕРА:5080` или `http://IP-АДРЕС:5080`. Точный адрес сервер печатает при запуске в строке `LAN:`.
5. Если Windows Firewall спросит доступ, разрешите входящие подключения. Если не спросит, создайте входящее правило TCP для порта 5080.

Трафик в локальной сети не шифруется: каталог рассчитан на доверенную сеть, доступ из интернета запрещён. Если шифрование понадобится позже, поставьте перед приложением обратный прокси (nginx/Caddy) с обычным сертификатом — менять код не придётся.

Окно сервера должно оставаться открытым. Папка `data` создаётся автоматически рядом с приложением. В ней лежит база SQLite `library.db` и файлы `uploads`. Для резервной копии проще всего нажать «Скачать ZIP» в интерфейсе: архив содержит согласованный снимок `library.db`, экспорт `library.json` и все файлы из `uploads`. При остановленном сервере можно скопировать всю папку `data` целиком; если в ней есть `library.db-wal` или `library.db-shm`, копируйте их вместе с базой. Также можно выполнить `powershell -ExecutionPolicy Bypass -File tools\backup-project.ps1`; скрипт исключает `backups`, `bin`, `obj` и не создаёт резервную копию внутри самой себя.

### Резервные копии данных и восстановление

Проверенная резервная копия базы и ассетов создаётся командой:

```powershell
powershell -ExecutionPolicy Bypass -File tools\backup-data.ps1
```

По умолчанию копия появится в `backups\data-backups\ГГГГММДД_ЧЧММСС`. В архив входят `library.db`, JSON-снимок `library.json`, архивный `library.json.old` и все файлы из `uploads`, в том числе не привязанные к карточкам. Скрипт получает ZIP через локальный API, сверяет размер файлов, проверяет SHA-256 архива и содержимого и запускает `MafLibrary.exe --check-library` на временно распакованной копии. Непроверенная копия не публикуется. PIN запрашивается интерактивно; для автоматизации используется защищённый DPAPI-файл.

Установка ежедневной задачи Windows (по умолчанию в 02:30, когда этот пользователь Windows вошёл в систему):

```powershell
powershell -ExecutionPolicy Bypass -File tools\install-data-backup-task.ps1
```

Время и срок хранения можно задать параметрами, например `-Hour 3 -Minute 15 -RetentionDays 45`. Сервер библиотеки должен быть запущен в назначенное время. PIN хранится зашифрованным средствами Windows для текущего пользователя. Удаление задачи без удаления копий: `powershell -ExecutionPolicy Bypass -File tools\install-data-backup-task.ps1 -Uninstall`.

Восстановление последней проверенной копии:

```powershell
powershell -ExecutionPolicy Bypass -File tools\restore-data.ps1
```

Для отдельной проверки backup без замены рабочей папки используйте `powershell -ExecutionPolicy Bypass -File tools\restore-data.ps1 -DataDirectory "$env:TEMP\maf-restore-test"`; тестовая копия появится в указанной папке и не меняет `data` проекта.

Сервер должен быть остановлен. Скрипт сверяет хеши, распаковывает копию во временную папку и проверяет базу/ассеты до замены. Перед заменой он просит ввести `RESTORE`; текущая папка `data` сохраняется в `backups\pre-restore`. Через `-BackupPath` можно указать конкретную датированную папку или ZIP рядом с манифестом. Параметр `-Confirm` отключает интерактивный вопрос и предназначен только для осознанного запуска.

`library.json.old` — архивный JSON, из которого база была перенесена при первом запуске. В обычной работе он не читается. Если удалить `library.db`, приложение при следующем старте попробует восстановить каталог из `library.json`, а затем из `library.json.old`.

Можно перенести данные в отдельную директорию, задав `MAF_DATA` до запуска. Адрес и порт меняются переменной `MAF_URLS`, например `http://0.0.0.0:5080`.

## Что реализовано

- Поиск по номеру, названию, категории, размерам и примечанию; сортировка и режим карточек/списка.
- Каталог хранится в SQLite (`data/library.db`): изменения фиксируются транзакциями, поэтому параллельные сохранения не теряются.
- Категории и карточки изделий. Полный номер изделия (`142.3`) не хранится отдельно: сервер собирает его из номера заказа и номера изделия, поэтому они не могут разойтись.
- PIN-защита изменений, добавления и удаления категорий, записей и файлов. По умолчанию PIN `admin`; для рабочей сети обязательно смените его.
- Ручная загрузка HTML-моделей (до 100 МБ на файл), рендеров, PDF и других документов. HTML открывается во встроенном изолированном просмотре либо новой вкладке. Файл модели не получает доступ к API библиотеки.
- Необязательный исходный сетевой путь с кнопкой копирования (работает и на HTTP через запасной способ).
- Импорт JSON в формате экспорта: новые изделия, категории и заказы добавляются, уже существующие изделия пропускаются.
- Экспорт JSON (описания изделий без самих файлов) и полная резервная копия одной кнопкой: ZIP с `library.db`, `library.json` и всеми файлами из папки `uploads`.

## Заметки для эксплуатации

- В текущей версии нет отдельных аккаунтов и журнала авторства правок; PIN общий для всех редакторов.
- Данные доступны всем, у кого есть доступ к серверу и порту в локальной сети. Сервер работает по HTTP и не должен быть доступен из интернета: PIN и содержимое каталога передаются без шифрования.
- Загрузка ограничена 100 МБ на файл. Увеличьте лимит в `Program.cs`, если потребуется.
- Для запуска на ПК без SDK опубликуйте проект на сервере командой `dotnet publish -c Release`, затем запускайте опубликованный `MafLibrary.exe` из папки publish. Установленный .NET Runtime должен соответствовать целевой платформе; для самостоятельного развёртывания опубликуйте self-contained под нужную архитектуру.
